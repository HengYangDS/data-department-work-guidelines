# 项目接入模板

> **性质**：项目局部适配清单；不复制或重述 [guidelines.md](../../guidelines.md)
>
> **目的**：让成员和 Agent 在项目内找到事实源、权限、风险与验收，而不是把通用准则留在抽象层。

## 1. 项目权威入口

| 项目问题             | 本地事实                       | 责任人     |
| -------------------- | ------------------------------ | ---------- |
| 当前目标与范围       | `<项目计划 / 工单 / 决策链接>` | `<待填写>` |
| 事实源与数据口径     | `<系统、数据集、文档链接>`     | `<待填写>` |
| 可执行权限与禁止动作 | `<本地 AGENTS / 安全规则链接>` | `<待填写>` |
| 测试、验收与发布门槛 | `<命令、检查或验收记录链接>`   | `<待填写>` |
| 中断、升级与恢复入口 | `<值班、负责人或运行手册链接>` | `<待填写>` |

## 2. 人与 Agent 的接入方式

1. 项目 `AGENTS.md` 先声明本地权威、权限与完成标准，再链接到本仓库的
   [最小加载](../../AGENTS.md#最小加载) 和 [任务路由](../../AGENTS.md#任务路由)。
2. 项目不得复制四条底线、场景卡或 Agent 协议；局部规则只补充本项目事实。
3. 涉及生产、敏感数据、删除覆盖、资金、安全合规或不可逆动作时，按
   [风险分级](../../guidelines.md#12-风险决定流程强度) 升级并保留人工验收。

## 3. 接入完成检查

- 项目成员能在一次任务启动中定位权威事实源、责任人和验收标准；
- Agent 能得到有界上下文、可执行权限和停止/升级条件；
- 本地事实与通用准则没有冲突；冲突存在时已显式升级，而非静默选择；
- 项目变更与验收记录可复查，且未将“命令运行”误写为“结果正确”。

> 接入完成只表示接入信息可用；不表示项目质量、团队能力或 Agent 结果已经得到证明。
