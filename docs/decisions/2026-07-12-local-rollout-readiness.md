# 决策：本地采用准备

> **状态**：本地已就绪；真实试用与远端发布待执行
>
> **权威正文**：[guidelines.md](../../guidelines.md)

## 问题与依据

读者体验重构已经证明入口、锚点、图形与文档结构可用，但尚未发生真实工作试用。
若此时直接要求成员“按准则执行”，容易把准则重新变成抽象要求；若另造推广表单或
复制规则，又会制造平行事实源。

依据是现行准则的“在真实工作中培养能力”“最小运行节奏”与“规则生命周期”：
新机制应嵌入真实 L1/L2 工作，以观察、证据和净增益决定保留，而不以宣讲或偏好定论。

## 决定

增加非规范性的本地采用准备包：

- 试用记录模板用于收集一项真实工作的事实、阻力、证据、限制与候选改进；
- 项目接入模板用于声明项目本地的事实源、权限、验收与恢复入口；
- 就绪校验脚本验证入口、模板边界与文档结构仍可使用；
- 所有通用规则继续只由 `guidelines.md` 规定。

## 增加、删除与净增益

| 项目   | 内容                                                               |
| ------ | ------------------------------------------------------------------ |
| 增加   | 本地试用记录、项目接入清单、就绪校验和本决策记录。                 |
| 删除   | 将试用建立在口头宣导、无证据反馈或复制通用规则之上的做法。         |
| 不增加 | 新会议、独立评分表、平行规则、团队质量结论或远端发布声明。         |
| 净增益 | 真实试用可留下可复查证据；项目可补足局部事实；机制仍保持最小必要。 |

## 验证

以下本地检查通过：

```bash
./scripts/validate-rollout-readiness.sh --render-dir /tmp/data-guidelines-rollout-readiness-qa
markdownlint-cli2 '**/*.md' '#.superpowers/**' '#.worktrees/**'
git diff --check
```

这些检查证明文档、路径、模板边界与渲染结构可用；不证明任何成员已完成试用。

## 不作的主张

本决定不主张远端项目已更新、团队已采用、成员能力已提高、Agent 已在真实任务中
合规运行，或任何候选改进已经成为团队规则。

## 复审条件

当至少有分析与决策、数据采用与生产、人智协作三类真实样本之一完成记录后，
由责任人复核：入口是否缩短路径、模板是否产生净增益、局部接入是否遗漏权限或验收、
以及候选改进应当纳入、修正、拒绝还是废止。
