# 命名决策：人智协作

> **日期**：2026-07-12
>
> **状态**：已接受
>
> **适用对象**：`guidelines.md` 中有关成员、Agent、模型、工具和自动化参与工作的通用规则

## 要解决的问题

“人—Agent 协作”中英混杂，且把具体技术实体抬升为总体关系名称；“人机协作”则容易把智能能力缩减为机械对象。两者都不足以清楚表达：人持有意向、判断、授权与责任，智能体承载可调用但受限的智能能力。

## 决定

总体关系名称采用 **人智协作**，章节名采用：

> **人智协作：边界、责任与验真**

其定义为：

> **人定其向，智扩其能；协作于事，归责于人。**

其中：

- **人**是承担意向、判断、授权与后果的责任主体；
- **智**是由 Agent、模型、工具和自动化承载的可调用智能能力；
- **协作**发生在同一事务中，但不产生责任主体的对等或转移。

技术上下文继续使用 **Agent（智能体）** 指具体实体。工作法采用：

> **借智成事，依实定论，归责于人。**

## 变更与净增益

| 项目 | 调整                                                    |
| ---- | ------------------------------------------------------- |
| 删除 | “人—Agent 协作”“人—Agent 治理”作为总体名称              |
| 增加 | “人智协作”的定义、责任关系与工作法                      |
| 保留 | Agent（智能体）的技术名称、权限限制、验证和人工验收要求 |

预期净增益是：去除中英混杂和“机器”隐喻；将智能能力与责任主体清楚区分；同时避免为命名增加新的流程或独立事实源。

## 验证与复审

- 文本验证：全项目术语一致，正文、入口、变更记录和复盘无旧总体名称残留。
- 运行验证：在首次三类试点中观察成员是否能自然地区分“借智”与“移责”。
- 复审触发：若“人智”被误解为人类智能、被用于稀释责任，或无法被项目局部规则准确引用，则重新评估名称与定义。
