# Design

## Context

The baseline is Git blob `ce3d090be258e65534781769e3e2fd5ab7439ef8`, the
1,240-line former `guidelines.md`, resolved from `f4242fb^:guidelines.md`.
The current source is `50af04643db12adb63727f16f1ff532bab3c9d76`. All fourteen
numbered sections, the opening cards, and the closing statement were read
against the seven current topic owners. Earlier audit records helped locate
questions but did not supply current coverage evidence.

The comparison asks whether the actor, action, condition, authority, evidence,
and stop or revisit boundary survive. It does not require matching paragraph
counts. Repeated instructions and former forms can share a current owner;
unique duties cannot disappear merely because a shorter page looks cleaner.

## Goals / Non-Goals

**Goals:** Restore distinct missing duties; make the complete comparison
reviewable; preserve task-first English guidance with one owner per rule; verify
and publish the accepted correction.

**Non-goals:** Restore the root monolith, introduce another rule or evidence
tree, translate the philosophical poem literally, reinstate a universal weekly
meeting, or stage real people and tasks to claim adoption.

### Correct the current source, not its history

Edit only the four topics with identified gaps. Preserve the historical Git
blob and earlier Change records as records of their time. The monthly and
quarterly floor reflects the later user correction to the earlier wholesale
cadence removal. No old archive is rewritten to imply it followed a lifecycle
that did not exist at the time.

Current review language must distinguish meeting acceptance criteria from
having authority to accept. Likewise, a professional judgment needs both
relevant competence and proximity to facts. A blocked dependency pauses its
affected action while independent, authorized work continues.

### Publish a compatible correction

Prepare `v5.2.3` only after reviewing the source correction. These additions
restore the former contract and clarify existing duties; they introduce no new
general approval, tool, or meeting requirement. Use the existing source-pinned
offline bundle machinery and declared platform matrices. A new lockfile is
unnecessary because the supply inputs already match current stable releases.
The source, signed release cut, release assets, and archive commit each need
their own current verification. Keep delivery tasks open until observed.

## Risks / Trade-offs

- **Compression loses a condition:** compare each repaired clause with the
  adverse case above and reread neighboring paragraphs for contradictions.
- **More text recreates the monolith:** add only missing duties at their owner,
  keep task-first entry, and inspect the rendered pages before acceptance.
- **A table certifies itself:** treat this as bounded editorial evidence;
  syntactic tests support only their stated properties.
- **An external dependency delays delivery:** continue independent source work;
  retain incomplete publication and shared-runtime tasks until verified.

against the resulting source and inspect rendered task pages. Run the full

for the signed source commit. Accept through the native ETHOS transitions,
