# Proposal

## Why

The adopter policy already declares that material governance changes must use the
official OpenSpec lifecycle and an ETHOS-owned companion scope. That contract
needs a real, current Work Lane exercise that proves its fail-closed negative
paths and its narrow bootstrap path without changing the normative guidelines.

## What Changes

- Record a local, current adopter validation of no-Change, incomplete-Change,
  valid-scope, uncovered-path, and scoped-bootstrap behavior.
- Bind the validation to one official OpenSpec Change, one active claim, and one
  dated Chronicle observation.
- Preserve the distinction between OpenSpec lifecycle, ETHOS scope admission,
  documentation correctness gates, and non-governance method packages.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `repository-governance`: subject=adopter-real-lifecycle-validation;
  reuse=extend; change=modify; facet:lifecycle=authoring,validation,archive;
  facet:surface=openspec,evidence,docs; facet:authority=openspec,claim,evidence.

## Out of Scope

- Changing `guidelines.md`, documentation correctness gates, or repository
  product behavior.
- Treating a Superpowers or other method package as a governance carrier.
- Claiming GitLab/GitHub publication, hosted CI, or organizational adoption.

## Impact

This Change adds only OpenSpec, claim, Chronicle, canonical governance-spec, and
local validation evidence for the adopter lifecycle contract.
