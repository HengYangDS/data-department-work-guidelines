# Proposal

## Why

The v4.0.1 English reading route is shorter than the last unified guideline.
Earlier Change tasks asserted full coverage, but a fresh obligation-level review
found specific duties that are weaker or absent. The retired criterion-system
draft is preserved outside the repository and must be reconciled, not restored
as a second rule tree. The repository also needs the MIT grant explicitly chosen
by its owner instead of the draft's unaccepted Apache proposal.

## What Changes

- Compare the last unified guideline and the retired draft against the current
  topic owners, recording a disposition for each distinct obligation.
- Restore genuine gaps in the existing English topics: evidence contrasts,
  hypothesis ranking, Agent stop and verification conditions, accountable
  management, and rule effective time. Do not restore a fixed meeting cadence.
- Add one standard MIT `LICENSE`, align the public entry and private tooling
  metadata, and reject a competing license statement.
- Verify reader routes and semantic counterexamples in addition to formatting,
  links, spelling, official OpenSpec, and ETHOS proof. Retire the temporary
  preservation package only after its unique useful meaning has been absorbed.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `guidance-discovery`: make the obligation-level reconciliation and the explicit
  exclusions observable without reinstating a root monolith or parallel rules.
- `repository-governance`: state the singular MIT license and consistent
  repository metadata as a checked publication contract.

## Impact

The Change affects the existing topic pages, README, `LICENSE`, package metadata,
repository checks, the current OpenSpec deltas, and release notes. It adds no
`rules/`, `playbooks/`, root `guidelines.md`, tracked evidence store, private
Change scope schema, or new lifecycle command. ETHOS and official OpenSpec
remain authoritative for material change and delivery. Historical commits and
the unaccepted draft are not retrospectively certified. Source verification,
local acceptance, Forge publication, and actual team use remain separate claims.
