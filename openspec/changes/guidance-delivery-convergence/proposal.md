# Proposal

## Why

The current signed edition has source and release checks, but its contributor
route does not explain how another maintainer builds the pinned offline bundle,
publishes it on each Forge, and verifies the resulting release. Internal YAML
metadata also precedes the title in ordinary rendered guidance. Passing source
checks does not settle either reader experience or release reproducibility.

## What Changes

- Recheck the seven current topics against the original guideline's 34-range
  disposition and the exact post-review diff. Repair only a demonstrated missing
  duty, qualifier, or counterexample at its existing semantic owner; preserve
  monthly and quarterly calibration without restoring the universal weekly
  meeting or fixed forms.
- Make the existing contributor route sufficient to build, sign, publish, and
  verify one release and its offline bundle on GitLab and GitHub independently.
  Keep credentials, host paths, and local caches out of tracked instructions.
- Reconcile reader-facing document metadata through an accepted ETHOS product
  contract. Do not add a repository-only metadata schema, a second document
  tree, or
  a lifecycle validator. Do not undertake device-specific or responsive design.
- Review the repository verifier's release-command and CI-topology assertions
  against the documented behavior. Tighten or simplify only where a concrete
  positive and negative case shows the current check is wrong or brittle.
- Reclassify the edition under SemVer and run the full local and
  installed-product checks. Once the source Change is complete, archive it
  natively; then publish the resulting signed source and bundle to both Forges,
  qualify the declared offline matrix, and retire owned temporary state.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `quality`: Current reader guidance must not make machine metadata the first
  visible content; source checks must preserve that boundary without replacing
  ETHOS registry authority.
- `repository-governance`: The release procedure must be reproducible from the
  tracked contributor route and observed independently on both Forges.

## Impact

The existing guidance pages and task map are review inputs, not a reason to
recreate the former monolith. Expected owners are `CONTRIBUTING.md`, a current
topic if a new semantic gap is proved, `tools/docs/` and tests only for a
demonstrated verifier defect, release metadata, and this official Change. The
metadata representation needs an accepted ETHOS product revision. Current page
metadata and default proof gates remain in force until that contract is
installed and verified. No team-adoption claim is implied.
