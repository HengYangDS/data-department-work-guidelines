# Proposal

## Why

The accepted English topics still contain a contradiction about cross-domain
ownership and omit several decision-useful qualifiers from the former accepted
guideline. The earlier 34-range disposition found many gaps, but its checked
tasks do not excuse a fresh comparison when a concrete counterexample appears.

## What Changes

- Correct the charter so shared professional interfaces cannot be mistaken for
  shared accountability; the data topic retains its one-lead rule.
- Require an explicit report when action authority conflicts with verified
  facts; neither authority silently overrides the other.
- Restore the distinction between platform-derived views and other data views,
  and name access-permission checks in the production-change boundary.
- Make an Agent completion report name when its verification ran, and make
  rejected or corrected Agent output visible as a quality signal even when no
  permission boundary was crossed. Keep time, security, compatibility, and cost
  constraints visible in a consequential delegation.
- Recheck these duties against the former source and the current reader routes;
  record the counterexamples in this Change, not a parallel rule book.
- Make the guidance useful at the point of work for both members and Agents:
  trace one source-grounded data decision from historical research through
  production and permitted use, and show how to communicate its stopping point.
  Keep one normative rule set; examples explain application, not new authority.
- Align specialized terms at their existing owners: task lead, authorized
  decision owner, reviewer, acceptor, data admission versus actual adoption,
  and verification versus acceptance and publication. Do not introduce a
  glossary that readers must consult before doing the work.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. The existing `guidance-discovery` requirement already requires editorial
review, a single owner for each duty, and evidence-bounded Agent reporting.
This repairs its current documentation rather than changing that contract.

## Impact

Only the existing English entry and topic owners and this official Change are
in scope. The example uses data-department work named in the former guideline;
it does not assert that a particular incident or adoption trial occurred.
No root monolith, new template, duplicate scope schema, separate evidence store,
or retrospective certification is introduced. Formatting and automated checks
cannot alone prove semantic equivalence or team adoption.
