# Proposal

## Why

DDWG validates a large document and a copied repository shape, but cannot yet
show that a member or Agent can find the right rule for a real data-department
task. Current OpenSpec specs include ETHOS product-family placeholders, decision
records contain transient delivery state, and tracked claim/Chronicle files
repeat historical repository activity without a current consumer. Green format
and lifecycle checks therefore overstate the quality of the guidance itself.

## What Changes

- **BREAKING** Replace the root `guidelines.md` monolith with one short,
  task-oriented documentation entry and cohesive normative topics under `docs/`.
  Preserve each necessary obligation through an explicit old-to-new disposition;
  do not preserve a path merely because it was previously linked.
- Separate the team rule, repository-change intent, observed proof, durable
  rationale, and real-work case boundaries. Retire the unsupported tracked
  `evidence/` root after unique historical facts are preserved in their actual
  owner or Git history. No new active claim or dated Chronicle is required by
  this Change merely to prove that it exists.
- Use lowercase `dr-NNNN-*.md` paths and one decision register. Keep only
  rationale that remains useful across Changes; retire time-bound status and
  redundant navigation pages without re-certifying historical work.
- Replace copied ETHOS product-family OpenSpec placeholders with DDWG-owned,
  observable guidance, quality, and repository-governance requirements.
- Replace shape quotas and stale command examples with checks of navigability,
  unique semantic ownership, current executable commands, links, rendering,
  and representative reader tasks.
- Converge GitLab's documentation job on the canonical runner capability tag
  while preserving GitHub's independent hosted job and the same local verifier.
  Complete source acceptance and each remote delivery claim from separate fresh
  evidence.

## Capabilities

### New Capabilities

- `guidance-discovery`: readers and Agents reach the applicable, uniquely owned
  rule and its limits from a task question without loading unrelated guidance.

### Modified Capabilities

- `quality`: validate meaningful documentation and decision boundaries without
  prescribing a fixed number of cards, diagrams, or historical evidence files.
- `repository-governance`: bind material changes to official OpenSpec and ETHOS,
  distinguish local source acceptance from dual-Forge delivery, and describe
  this repository's actual publication policy rather than historic repair steps.
- `adapters`, `assistant-projections`, `command-plane`, `contracts`,
  `distribution`, `kernel`, `proof-hosts`: remove copied ETHOS product-family
  requirements that DDWG does not own.

## Impact

The Change affects the root entrypoints, normative documentation, decision
records, OpenSpec specs and configuration, ETHOS profile and release bindings,
repository-local validation, CI projections, historical tracked evidence,
CHANGELOG, and linked documentation. It does not assert that team practice has
improved or that either Forge has executed the resulting revision. Foreign
Work Lanes, credentials, host runner registration, and external project records
remain outside this source Change.
