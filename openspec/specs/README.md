# OpenSpec Capability Specs

Each capability directory contains accepted behavior in `spec.md`. Capability
paths name cohesive, durable behavior, not packages or implementation tasks.
Under **Modified Capabilities**, a proposal names the exact existing path under
`openspec/specs/`. **New Capabilities** may introduce a new cohesive path through
the official Change's deltas. Follow the official artifact fields and directory
shape; repository-private metadata does not extend them.

| Your concern              | Capability                                             |
| ------------------------- | ------------------------------------------------------ |
| Find the right guidance   | [Guidance discovery](guidance-discovery/spec.md)       |
| Apply it to actual work   | [Work practice](work-practice/spec.md)                 |
| Maintain readable source  | [Document quality](quality/spec.md)                    |
| Establish checked results | [Verification](verification/spec.md)                   |
| Supply maintenance tools  | [Tool supply](tool-supply/spec.md)                     |
| Change or accept source   | [Repository governance](repository-governance/spec.md) |
| Publish or retire assets  | [Publication](publication/spec.md)                     |

Requirements enter these files through official synchronization; that does not
certify implementation or close the [active Change](../changes/native-document-quality/tasks.md).
