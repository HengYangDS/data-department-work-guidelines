# 文档注册契约收敛记录

> **日期**：2026-07-12
>
> **对象**：准则仓库内的全部 `docs/**/*.md` 文档
>
> **范围**：元数据唯一性、文档状态、可见导航区段与本地可读性

## 观察

此前的正式 proof 已覆盖 Markdown、链接、锚点、Mermaid、语义文档拓扑、证据与生成物边界；
但独立 `ethos quality docs-registry --json` 仍可复现以下遗漏：部分文档没有机器可读的
`subject`、`role`、`state`、`relations`，多数现行文档没有可见的状态、目的和参见入口，且
治理政策与 adopter 决策复用了同一 subject。

## 修复原则

1. 不以隐藏注释或无意义占位绕过检查；状态、目的和参见应被成员与 Agent 直接看见。
2. 元数据描述文档的功能而非重复正文；每个 subject 只指向一个文档对象。
3. 已归档的计划、设计与复盘保留可检索元数据，但不伪装为现行规则入口。

## 验证

```bash
ethos quality docs-registry --json
./scripts/validate-docs.sh
./scripts/validate-rollout-readiness.sh
ethos prove --execute --scope docs --expect-head "$(git rev-parse HEAD)" --json
```

## 限制

本记录证明的是本地文档治理与可读性收敛；不证明 GitLab 已渲染、远端已发布，或团队已完成
真实试用。
