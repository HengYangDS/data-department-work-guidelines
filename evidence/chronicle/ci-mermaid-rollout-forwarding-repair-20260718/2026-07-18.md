# Chronicle: CI Mermaid rollout forwarding repair — 2026-07-18

## Observation

GitHub Actions documentation run `29641340007` for commit `e753998` passed the
first direct documentation validation with the canonical hosted renderer
selection, then failed during the rollout-readiness validation. The job log
shows that the second Mermaid invocation started Chrome without a usable
sandbox. Inspection of the shared verifier found that it called
`validate-rollout-readiness.sh` without forwarding its already validated
renderer option.

## Action

This Change forwards the same validated repository-relative renderer option to
rollout-readiness validation. It adds an executable regression that proves the
shared verifier passes the option to both direct and nested validation, and
rejects an unsupported selection before any validation command runs.

## Evidence Boundary

This Chronicle records an external failure observation and a local repair
boundary. It does not prove current-HEAD proof, local acceptance, GitLab or
GitHub publication, hosted rendering success, remote rendering, or
organizational adoption.

## Revisit

After an eligible published ref triggers each provider, inspect the fresh runs
at that SHA. If either renderer still fails, preserve its log and open a new
Change rather than broadening the CI-only compatibility exception.
